# 多标注语料冲突裁决台

多名标注者对同一份 UTF-8 文档提交字符区间标注，系统校验区间合法性、按
**区间重叠比例 × 标签一致 × 标注者权重** 为候选打分，用 **OR-Tools CP-SAT**
在「可嵌套 / 互斥」标签约束下求**总得分最大的确定性共识**；裁决者可以
逐条查看未采纳标注及其支持者、强制采纳/驳回并注明理由，最终生成带
**输入快照、算法参数、版本号与 SHA-256** 的不可变共识报告。

- 后端：Python 3.12 · FastAPI · SQLite · OR-Tools（CP-SAT）
- 前端：原生 HTML / CSS / JavaScript（无构建步骤、无前端框架）
- 编排：Docker Compose（nginx 托管静态页面并反向代理 API）

---

## 一、启动步骤

需要 Docker（含 Compose 插件）。在仓库根目录执行：

```bash
docker compose up --build -d
```

首次启动会构建两个镜像并初始化 SQLite 数据库（存放在 Docker 卷
`adjudication-data` 中）。

访问入口：

| 入口 | 地址 |
| --- | --- |
| **裁决台 Web 页面** | <http://localhost:8080/> |
| 共识报告页面示例 | <http://localhost:8080/report.html?id=1>（生成报告后可打开） |
| API 健康检查 | <http://localhost:8080/api/health> |
| API 文档（Swagger） | <http://localhost:8080/docs> |

停止与清理：

```bash
docker compose down            # 停止，保留数据卷
docker compose down -v         # 同时删除数据库卷（清空全部数据）
```

## 二、使用流程（页面对应六个步骤页签）

1. **文档导入**：选择 UTF-8 文本文件（`.txt`）与词元边界 JSON 文件
   （格式 `[[start,end], ...]`，半开区间 `[start,end)`、按起点升序）。
   重新导入会产生一份**新文档**，旧文档与旧报告保持不变。
   示例文件见 [`examples/`](examples/)。
2. **标签与规则**：定义标签，并声明标签关系：
   - `nested`（方向性）：**外层标签**可以严格包含**内层标签**；
   - `mutex`：互斥；
   - 未声明关系的两个不同标签**默认互斥**，同一标签的区间重叠恒为冲突。
3. **标注者权重**：每项目 2～8 名标注者，权重 1～10，可随时修改。
4. **提交标注**：每行 `start,end,标签名`，按标注者整批替换提交。
   越界（超出文档）或切开词元（与区间相交的词元未被完整包含）的区间
   会导致**整批拒绝**，不写入任何数据。
5. **裁决台**：
   - 「新建裁决」求最优共识；表格逐条列出**未采纳标注及其支持者**
     （其他标注者同标签、相交的区间与 Jaccard 重叠比例）；
   - 可对任意候选 **强制采纳 / 强制驳回**，必须**注明理由**；
     覆盖使问题无解时会明确报错（不会生成报告）；
   - 「生成不可变共识报告」后裁决永久冻结。
6. **共识报告**：打开 `report.html?id=N` 查看完整报告，或下载规范 JSON。

## 三、算法说明

### 3.1 候选与得分

- **候选区间**：所有输入标注按 `(起点, 终点, 标签)` 去重得到。
- **候选得分**：

  ```
  score(c) = Σ_标注者 a  weight(a) × max{ Jaccard(c, b) | b 是 a 提交的、与 c 同标签且相交的标注 }
  ```

  - 完全重合的标注 Jaccard = 1，故每名标注者对一个候选**至多贡献其权重**，
    不会因重复/多份重叠标注而虚增得分；
  - 部分重叠按交并比折算（切开词元的区间在提交阶段即被拒绝，
    因此这里的重叠均来自合法边界上的分歧）。
- 得分乘以 `SCORE_SCALE=1000` 四舍五入为整数交给 CP-SAT。

### 3.2 约束与优化

- 冲突对：同标签区间相交；不同标签相交但未声明嵌套（含显式互斥、
  交而不含、同起止点跨标签）。声明了 `outer ⊇ inner` 的严格包含关系允许共存。
- 决策变量 `x_c ∈ {0,1}`，目标为 `max Σ score_int(c)·x_c`，
  冲突对加 `x_c + x_d ≤ 1`；裁决者覆盖则固定 `x_c = 0/1`。

### 3.3 确定性与平局裁决

1. 先求出最优总得分 `B*`；
2. 在「总分必须等于 `B*`」的前提下，按候选顺序
   **（区间起点 → 区间终点 → 标签名 → 标签 id）升序**逐个试探：
   靠前的区间若仍能补全为某个最优解，则固定为采纳，否则固定为不采纳。

   因此无论求解器内部搜索顺序如何，共识结果唯一可复现。
3. CP-SAT 使用固定参数：`random_seed=20261001`、单线程、10 秒上限。

## 四、不可变报告

- 每次生成报告获得该项目下**单调递增的版本号** v1、v2、……；
- 报告 JSON 包含：应用名/版本、OR-Tools 版本、生成时间、项目/文档/裁决标识、
  **完整输入快照**（原文、词元、标签与关系、标注者权重、全部输入标注）、
  **算法参数**（计分公式、约束说明、平局规则、放大系数、CP-SAT 参数）、
  共识结果（候选得分、采纳情况、覆盖与理由、未采纳标注及支持者）；
- 对报告内容做规范序列化（键排序、无空白）后计算 **SHA-256**，随报告存储；
- `reports` 表只有 INSERT：重新导入文档、增删标签/关系、修改权重都只影响
  **之后**新建的裁决与报告，**任何旧报告都不会被重算或改写**。

## 五、本地（不用 Docker）运行

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

然后直接用任意静态服务器托管 `frontend/`（开发时也可只访问
<http://localhost:8000/docs> 调试 API；前端通过同源 `/api` 访问后端，
生产请使用 Compose 中的 nginx 代理）。

## 六、目录结构

```
docker-compose.yml
backend/            FastAPI + SQLite + OR-Tools
  app/main.py       HTTP 路由
  app/solver.py     CP-SAT 建模与确定性平局裁决
  app/service.py    区间校验、候选/得分、报告快照
  app/db.py         SQLite 建表（reports 仅 INSERT）
  e2e_test.py       端到端冒烟测试（TestClient，覆盖校验/求解/覆盖/冻结/不可变）
frontend/           原生 JS 页面（经 nginx 托管并代理 /api）
examples/           示例 UTF-8 文档与词元边界
```

## 七、自动化测试

```bash
pip install -r backend/requirements.txt httpx
python3 backend/e2e_test.py
```

测试使用独立临时数据库目录（`DATA_DIR=/tmp/adj-test`），覆盖：
UTF-8 与词元边界校验、越界/切开词元整批拒绝、2～8 名标注者与 1～10 权重限制、
候选得分（权重 × 最大 Jaccard、同标注者不重复计权）、互斥/嵌套约束、
平分时按 (起点,终点,标签) 的确定性裁决、强制采纳/驳回（含理由与撤销）、
覆盖冲突判 INFEASIBLE、报告版本递增，以及
**改权重/加标签/重新导入文档后旧报告字节级不变**。
